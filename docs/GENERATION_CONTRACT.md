# Контракт генерации и проверок

## Выходные файлы

Генератор публикует `NAME.C8`, `NAME.TXT` и `NAME.manifest.json` (имя IQ задаёт
пресет). TXT содержит фактические `sample_rate` и `center_frequency` в Hz.
Manifest содержит SHA-256 IQ/TXT, длительность, размер, формат, clipping,
снимок пресета, версию сборки/lockfile, алгоритм шума и допущения модели.
Хеш IQ считается потоково. Проверка перед переносом:

```sh
cargo run --release --bin verify_artifact -- /path/NAME.C8
```

Каждый файл публикуется атомарным rename, однако три rename не являются одной
транзакцией. Manifest публикуется последним. Ошибка после публикации IQ может
оставить несовпадающие sidecar; такой набор проверка отвергает. После сбоя питания
USB проверка обязательна. Replay сам manifest не проверяет. Метка `-dirty` означает,
что commit не описывает все исходники сборки; для воспроизведения нужен checkout.

## Полоса BOC

`output.bocMode`: `auto` (по умолчанию), `full`, `boc11`. Для Galileo E1,
GPS L1C и BeiDou B1C full требует `Fs/2 > |1575.42 MHz − center| + 7.161 MHz`,
чтобы главные лепестки BOC(6,1) помещались в полосу. `full` с недостаточной Fs
отклоняется. `auto` при недостаточной полосе использует BOC(1,1), `boc11` делает
это явно при любой Fs. При 4.2 MS/s режим auto — упрощённый BOC(1,1).
Это не реализация аналогового anti-alias фильтра: прямоугольные поднесущие имеют
гармоники вне главных лепестков. GPS L1C TMBOC переключается на чипах 0/4/6/29
каждой группы 33 чипов, а не по миллисекундам.

## Динамика

Орбита/геометрия/Доплер обновляются каждую миллисекунду, видимость — каждую
секунду, выбор эпохи RINEX — каждые 90 секунд. Часы включают переход недели.
Продолжающийся канал сохраняет объект с NCO; новый канал инициализируется по
текущему времени. Новые nav-данные принимаются на границе навигационного блока,
а не посреди кодового слова. При смене IOD физическая модель использует новую
эпоху сразу, тогда как навигация доходит до своей границы: это оговорённое окно,
а не модель непрерывной реальной трансляции эфемерид. Нужны дальнейшие сравнения
на специально подготовленных скачках IOD. Окончание пригодности всех эфемерид
может дать участок только с шумом; количество переходов записано в manifest.

## Атмосфера Galileo

**NeQuick G в распространении не реализован.** Galileo использует GPS Klobuchar
из RINEX как явно упрощённую модель, с масштабированием задержки по квадрату
отношения частот. Навигационные страницы передают свои NeQuick-коэффициенты,
которые нельзя трактовать как восемь коэффициентов Klobuchar. Поэтому включение
NeQuick-коррекции в приёмнике не обязано устранить смещение PVT. Для изолированной
проверки навигации сравнивать также решение с отключённой коррекцией атмосферы.
При отсутствии GPS iono остаётся ночной базовый член 5 ns × mapping, а не ноль.
Klobuchar проверяется численными векторами независимого RTKLIB `ionmodel` в
`tests/atmosphere_reference.rs`; это не подтверждение полноценной NeQuick G.

## Источники проверки

- [RINEX 3.04](https://www.rtcm.info/RINEX_3.04.IGS.RTCM_Final.pdf): Galileo
  data source не помещается в u8; 517 соответствует I/NAV с часами E1/E5b,
  258 — F/NAV с часами E1/E5a. Для нижней частоты задержка равна gamma×BGD,
  gamma=(fE1/fLow)²; для E1 — BGD соответствующей пары.
- [GPS IS-GPS-800H](https://www.navcen.uscg.gov/sites/default/files/pdf/gps/IS_GPS_800H.pdf): TMBOC.
- [GNSS-SDR GNAV](https://github.com/gnss-sdr/gnss-sdr/blob/v0.0.20/src/core/system_parameters/GLONASS_L1_L2_CA.h):
  позиции полей и независимые уравнения контроля чётности.
- [RTKLIB ionmodel](https://github.com/tomojitakasu/RTKLIB/blob/rtklib_2.4.3/src/rtkcmn.c):
  численный эталон Klobuchar.
- [RustCrypto SHA-2](https://docs.rs/sha2/0.11.1/sha2/): потоковый SHA-256.
